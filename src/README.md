# Jarvis Source Code Organization

Исходный код Jarvis организован по функциональным модулям:

## Структура директорий

```
src/
├── core/              # Основная орхестрация и точка входа
│   ├── orchestrator.py    # Главный движок Jarvis (обработка команд, LLM)
│   ├── entry_point.py     # Vosk слушатель и голосовой ввод
│   └── bootstrap.py       # Инициализация и запуск системы
│
├── services/          # Фоновые сервисы и демоны
│   ├── daemon_swarm.py    # Наблюдатели системных событий
│   ├── recon_daemon.py    # Разведка сети и системы
│   ├── sentinel.py        # Безопасность и мониторинг
│   └── watch_service.py   # Глубокое наблюдение за событиями
│
├── memory/            # Управление памятью и состоянием
│   ├── engine.py          # Хранилище дол Kronosгосрочной памяти
│   ├── storage.py         # Векторная база данных (Mnemosyne)
│   ├── ephemeral.py       # Временные данные и выполнение кода
│   └── snapshot.py        # Снимки состояния системы
│
├── ui/                # Пользовательский интерфейс
│   ├── hud.py             # HUD и визуализация (PyQt6)
│   ├── window_manager.py   # Управление окнами KWin
│   └── pixel_renderer.py   # Рендеринг пикселей для дисплея
│
├── audio/             # Обработка аудио
│   └── fft_analyzer.py    # FFT анализ и Piper TTS
│
├── network/           # Сетевые утилиты
│   └── scanner.py         # Сканирование сети (nmap)
│
├── security/          # Безопасность и выполнение
│   └── execution.py       # Shadow execution и sandboxing
│
└── common/            # Общие утилиты
    ├── event_bus.py       # Шина событий
    ├── parser.py          # Парсинг ответов и bash
    ├── singleton.py       # Singleton паттерн
    └── repair.py          # Быстрое исправление ошибок
```

## Соглашения по именованию

- **Модули**: snake_case (`orchestrator.py`, `window_manager.py`)
- **Классы**: PascalCase (`JarvisMain`, `DaemonSwarm`, `KWinOrchestrator`)
- **Функции**: snake_case (`compute_bands()`, `stream_nmap()`)
- **Константы**: UPPER_CASE (`LLAMA_MODEL_PATH`, `WEAVER_MEMORY_FACTS`)

## Импорты

После реоргнизации все импорты используют полные пути:

```python
# Правильно ✓
from src.core.orchestrator import Jarvis
from src.common.event_bus import EventBus, EventType
from src.memory.engine import ChronoMemory

# Неправильно ✗ (больше не работает)
from core import Jarvis
from event_bus import EventBus
```

## Как запустить

```bash
# Бессмертный запуск (рекомендуется): внешний супервизор стережёт Джарвиса
python -m src.core.supervisor            # демонизируется, переживает закрытие терминала
python -m src.core.supervisor status     # жив ли супервизор и bootstrap
python -m src.core.supervisor restart    # перезапустить bootstrap немедленно
python -m src.core.supervisor stop        # единственный способ корректно остановить всё

# Прямой запуск без супервизора (для отладки)
python -m src.core.bootstrap

# Запуск тестов
pytest tests/ -v

# Линтинг
ruff check .
```

## Бессмертие и горячая перезагрузка

Джарвис спроектирован как **самовосстанавливающаяся** сущность — двумя слоями:

**Слой 1 — горячая перезагрузка кода (`src/core/immortal.py`).**
Внутри процесса bootstrap живёт `FileChangeWatcher`: следит за `src/` и
`config/`. Как только вы отредактировали файл или сделали `git pull`, процесс
делает `os.execv` и поднимается со **свежим кодом и тем же PID** — все изменения
подхватываются автоматически, вручную перезапускать ничего не нужно. Сервер
инференса llama-cpp живёт в отдельном процессе, поэтому при перезагрузке кода
модель остаётся «тёплой» в RAM.

> Почему `os.execv`, а не `importlib.reload`? Живое Qt+asyncio+потоки-приложение
> после `importlib.reload` остаётся в полусломанном состоянии (слоты и синглтоны
> держат ссылки на старые классы). `os.execv` даёт честный чистый старт нового
> кода без потери дескрипторов — это и есть «корректно подхватить все изменения».

**Слой 2 — внешний супервизор (`src/core/supervisor.py`).**
Демон, который стережёт `python -m src.core.bootstrap` и поднимает его при
**любом** завершении: краш, OOM-килл, `kill`, Ctrl+C. Сам супервизор при старте
делает double-fork и `setsid`, поэтому закрытие терминала его не убивает.
Именно поэтому **остановка `python -m src.core.bootstrap` не убивает Джарвиса** —
супервизор за ~секунду поднимает его обратно. Падения получают экспоненциальный
backoff (1→2→4→…→30с), плановая перезагрузка кода — мгновенный подъём.

**Продакшн — systemd (`config/jarvis.service`).**
`ExecStart` запускает супервизор в foreground, `Restart=always` + `WatchdogSec=30`
ловят даже зависший event-loop. Установка: `scripts/install_service.sh`.

## HUD — живая сущность, строго зафиксированная (`src/ui/hud.py`)

- **Позиция намертво зафиксирована.** Рамка по периметру + круглое «пятно» в
  правом нижнем углу (ratio `0.88, 0.86`) НИКОГДА не съезжают: запросы на
  репозицию (`set_core_position`) игнорируются, периодический «дрейф» по
  квадрантам убран — остался только pin поверх окон (KWin под Wayland иначе
  сбрасывает флаги keepAbove/skipTaskbar).
- **Рамка дышит в такт голосу.** В состоянии `SPEAKING` цвет и альфа рамки
  лерпуются `dim → peak` по уровню голоса (`FFT level`), конкурирующие
  QPropertyAnimation глушатся, чтобы пульсом владел только звук.
- **Пятно — индикатор речи с нулевой задержкой.** Круглая сфера в углу видна
  ТОЛЬКО когда Джарвис реально произносит звук (`state == SPEAKING` и
  `fft_level > 0.05`); в тишине её нет. Радиус и яркость пульсируют по `FFT
  level`. Энергия берётся из `PiperFFTPump` (~100 Hz) прямо из PCM-потока перед
  `aplay`, с back-pressure от звуковой карты — поэтому пульс совпадает с голосом
  практически без задержки. HUD перерисовывается 30 fps, чисто на QPainter
  (никакого GL — он валил Intel N100).

## Голос Джарвиса (TTS post-processing)

Синтез речи: **Piper** (`piper/ru_RU-dmitry-medium.onnx`) → raw PCM →
цепочка эффектов **sox** → `aplay`. Цепочки заданы в
`src/core/orchestrator.py::SOX_PROFILES`.

Цель DSP — приблизить нейтральный TTS к **кино-Джарвису** (Пол Беттани):
тёплый гладкий британский баритон, ровная подача, лёгкая «хай-фай»-комната.
Сознательно **без** фейзера и «шиммера» на верхах — они звучат робото-/сай-фай,
прочь от оригинала. Профили по состоянию:

| Профиль         | Когда                                  | Характер                          |
|-----------------|----------------------------------------|-----------------------------------|
| `normal`        | обычный ответ                          | тёплый баритон, тонкая комната    |
| `idle`          | IDLE state                             | глубже, медленнее, просторнее     |
| `alert`         | ALERT / destructive gate               | сухой, собранный, «впереди»       |
| `night_stealth` | темно (Pixel-сенсор) или ≥23ч / ≤6ч    | тёмный, тёплый, тихий             |

**Потолок метода (важно):** sox формирует тембр/стиль/пространство, но НЕ
переносит саму идентичность голоса актёра — спикер под капотом остаётся
русский мужской Piper. Для точного клонирования тембра Беттани нужен слой
**voice conversion** (RVC / so-vits-svc), обученный на сэмплах JARVIS, между
Piper и sox. Параметры цепочки можно валидировать на синтетическом тоне:

```bash
sox -n -t raw -r 22050 -e signed -b 16 -c 1 /tmp/t.raw synth 1 sine 130 sine 260
sox -t raw -r 22050 -e signed -b 16 -c 1 /tmp/t.raw -d <эффекты-профиля>
```

> Примечание: при частоте 22050 Гц частота Найквиста = 11025 Гц, поэтому
> shelf/eq выше ~11 кГц бессмысленны (теплота строится на низах и гладкости).
